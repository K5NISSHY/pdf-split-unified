## 1. 要件定義

### 1.1 目的・背景

これまで別リポジトリで2本作った「PDFを1ページずつに分割し、Excelのセル値でファイル名を付ける」ツールは、
UI・検証・一時書き出し・ロールバックのロジックがほぼ同一で、違いは**ファイル名の付け方だけ**だった。

- **PDF-Split-Rename**: 指定セル1つの値を共通のベース名にし、`ベース名_001.pdf` のように連番を付ける
- **PDF-Split-Rename-By-Cell**: 開始セルから**下方向**へページ数分読み、セル値そのままのファイル名にする（連番なし）

2本を「ベース共通・1ウィンドウ統合」の1アプリにまとめ、切替操作だけで両方を使えるようにする。
統合により、共通の事前検査（空欄・不正文字・予約名・重複・数式キャッシュ）・安全な書き出し（一時フォルダー経由・失敗時ロールバック）を1本化し、今後の修正を1箇所で済ませる。

### 1.2 機能要件

| ID | 要件 | 優先度 |
|---|---|---|
| FR-1 | `起動.bat` ダブルクリックで**単一のメインウィンドウ**が開く（Python 3.10+ / Tkinter） | 高 |
| FR-2 | ウィンドウ上部に**共通入力欄**（分割するPDF / Excelファイル / シート / 出力先フォルダー）を置く。両モードで同じ欄を共有し、入力し直しにしない | 高 |
| FR-3 | 下部に**モード切替**（タブ 2枚）を置く。タブ1「セル値＋連番」/ タブ2「セル別（連番なし）」。切替で既存の入力は保持される | 高 |
| FR-4 | タブ1（セル値＋連番）: 指定セル1つの値をベース名とし、`{ベース名}_{ページ番号:03d}.pdf` で出力する（先頭は `001`、1000ページ超では桁数が伸びる） | 高 |
| FR-5 | タブ2（セル別）: 開始セルから**同じ列を下方向**へページ数分読み、`{セル値}.pdf` で出力する（連番なし） | 高 |
| FR-6 | 実行前に全件検査し、1件でも不正があれば**処理を開始しない**: 空欄セル / ファイル名に使えない文字（`\ / : * ? " < > |`・制御文字）/ 末尾の空白・ピリオド / Windows予約名（CON, AUX, COM1…） / 大文字小文字を区別しない**重複名**（タブ2） | 高 |
| FR-7 | 数式セルは計算せず、Excelブックに保存済みの計算結果を使う。結果が無い・空・エラー値（`#REF!` 等）の場合は再計算を促す日本語エラーを表示して中止する | 高 |
| FR-8 | 出力予定ファイルが1つでも既存なら**上書きせず中止**（既存ファイル名を最大8件＋件数で提示） | 高 |
| FR-9 | 全ページを出力先内の一時フォルダーへ書き出してから移動する。途中で失敗した場合は作成済みの出力を削除して後片付けする。**元のPDF・Excelは変更しない** | 高 |
| FR-10 | 暗号化PDFは空パスワードで解除を試み、開けなければ日本語エラーを表示して中止する。破損PDF・読み込めないExcelも日本語エラーで中止する | 高 |
| FR-11 | 成功時は「Nページを分割しました／保存先」をダイアログ表示し、エラーは元の2ツールと**同じ文言**で表示する（既存ユーザーの操作感を壊さない） | 中 |
| FR-12 | 既存2リポジトリの単体テストを1ファイルに統合して維持し、共通コアのテストを追加する（`python -m unittest -v` で実行できる） | 高 |
| FR-13 | 独立検証スクリプト `tools/verify_independent.py` を持つ。実PDF（3ページ）と実Excelを一時作成し、両モードで分割結果・ファイル名・ページ数・既存ファイル保護・重複検出を機械的に確認して合否を出力する | 高 |
| FR-14 | **ファイル名プレビュー**: 「分割を実行」の前に「プレビュー」で、出力予定ファイル名の一覧をウィンドウ内の一覧欄（最大100行＋「ほかN件」）に表示する。行には次の印を付ける: 出力先に既存ファイルがある行は `[既存]`、タブ2で大文字小文字を区別しない重複がある行は `[重複]`。プレビューは**書き出しを行わず**、FR-6 の検査対象（空欄・不正文字・予約名・数式キャッシュ）もその場でエラーとして一覧下に表示する | 高 |
| FR-15 | プレビュー後に入力（PDF/Excel/シート/セル）が変わったら、一覧を**「要更新」表示**にする（古い一覧のまま実行しない安心感）。実行時は常にその時点の入力で再計算する | 中 |

### 1.4 設計方針（統合のかたち）

- **単一ウィンドウ＋タブ切替**（ ttk.Notebook ）。共通欄を上部に固定し、モード別の入力欄（セル番地 or 開始セル）だけをタブ内に置く
  - 代替案: ラジオボタンで同一フォーム内の行を差し替え。→ 採用しなかった理由: タブなら既存2画面のレイアウトをそのまま保て、説明文言を各自のタブに置けるため（2026-11-20 ユーザー承認によりタブ方式で確定）
- **プレビューは名前生成のみの読み取り専用処理**とし、実書き出し（`write_pages`）とは別の経路を通す。ファイル名生成は実行時と同一関数を共有する（表示と実結果のズレを防ぐ）
- **ファイル構成案**（新規作成が許可されるファイルは以下のみ）
  - `pdf_split_unified.py` — GUI（共通欄＋タブ2枚＋プレビュー一覧欄）、エントリポイント
  - `split_core.py` — 共通コア（Excel読取・検証・PDF読み込み・一時書き出し/ロールバック・既存チェック）
  - `modes.py` — 2モードの「出力ファイル名リスト作成」のみ
  - `preview.py` — プレビュー行の生成（ファイル名＋`[既存]`/`[重複]` 判定）。GUIは表示のみ担当し、判定ロジックはここに置く
  - `test_pdf_split_unified.py` — 統合テスト（両モード＋共通コア＋プレビュー判定）
  - `tools/verify_independent.py` — 独立検証
  - `起動.bat`, `README.md`, `LICENSE`, `LICENSE.ja.md`, `.gitignore`
- **参考コードの写し**: `refs/PDF-Split-Rename/`, `refs/PDF-Split-Rename-By-Cell/`（読み取り専用。実装の元ネタとして同梱し、コミット対象に含める）
- **バージョン**: 1.0.0（統合初版）

### 1.5 対象外（スコープ外）

- PDFファイル選択時の**ページ画像プレビュー**（PDF内容の描画。ファイル名プレビューは FR-14 で実装し、ページ内容の表示は対象外）
- 範囲指定（例: 3〜10ページだけ）／複数PDFの一括分割
- 出力ファイルの**上書き実行**（既存は常に中止）／既存ファイルの削除
- 暗号化PDFの**パスワード入力欄**（従来どおり解除済みPDFを用意する）
- PDFドラッグ＆ドロップ起動、アイコン・テーマ装飾、セットアップexe化
- Excelの新規作成・セルへの書き込み（読み取り専用）

## 2. 機能定義（スクリプト毎の入出力・データ仕様）

### 2.1 `split_core.py`（共通コア）

| 関数 | 入力 | 出力・挙動 |
|---|---|---|
| `validate_filename_base(name, cell_address)` | セル値の文字列, 位置表記 | 検証済み文字列を返す。不正（不正文字/末尾空白・ピリオド/予約名）は `ValueError`（セル位置入りの日本語メッセージ） |
| `parse_cell_address(cell)` | `A1` / `$B$3` 形式 | `(列字母, 行番号)`。不正形式は `ValueError` |
| `read_cell_values(excel_path, sheet_name, addresses)` | 読み取りたいセル番地のリスト | `{番地: 検証済み文字列}`。数式キャッシュ無し・エラー値・空欄は `ValueError`。`data_only=False` と `True` の2回読みを1回にまとめた実装可（挙動は既存と同じ：数式セルは保存済み結果を採用） |
| `load_pdf(pdf_path)` | PDFパス | 暗号化検査済みの `PdfReader`。失敗は `ValueError` |
| `write_pages(reader, filenames, output_dir)` | ページ列, ファイル名リスト（同数） | 一時フォルダーへ書出し→出力先へ移動→一時削除。既存ファイル検査（`FileExistsError`）・失敗時ロールバック。**戻り値: 出力Pathリスト** |

- 定数: `INVALID_FILENAME_CHARS`, `WINDOWS_RESERVED_NAMES`, `EXCEL_MAX_ROW`（既存値を踏襲）

### 2.2 `modes.py`（モード別のファイル名生成）

| モードID | 表示名 | 追加入力 | 出力ファイル名の規則 |
|---|---|---|---|
| `base_seq` | セル値＋連番 | セル番地（初期値 `A1`） | `{検証済みセル値}_{ページ番号:03d}.pdf` |
| `per_cell` | セル別（連番なし） | 開始セル（初期値 `A1`） | 開始セルから同列下行きページ数分 → `{検証済みセル値}.pdf`（大文字小文字無視の重複検査あり） |

- 各モードは `build_filenames(excel_path, sheet, cell, page_count) -> list[str]` の形に統一する

### 2.3 `pdf_split_unified.py`（GUI）

- 共通欄: PDF / Excel / シート（Combobox, Excel選択時にシート一覧＋アクティブシート初期選択） / 出力先（PDF選択時はPDFのあるフォルダーを初期値）
- タブ内: モード別セル入力欄と説明ラベル（文言は既存2ツールを踏襲）、**ボタンは「プレビュー」と「分割を実行」の2つ**（共通欄の下。現在アクティブなタブのモードで動作）
- プレビュー一覧: `ttk.Treeview`（列: ページ番号 / 出力ファイル名 / 状態）＋縦スクロールバー、**表示12行程度**（データは全件保持し、100件超は末尾に「ほか N 件」行）。状態列に `[既存]` / `[重複]`。一覧下に表示件数とエラーメッセージ欄
- 共通欄・セル欄のいずれかが変わったら一覧を消して「入力変更あり: プレビューを更新してください」表示（FR-15）
- 未入力欄があれば警告ダイアログ、実行結果は FR-11 のとおり
- ウィンドウタイトル: `PDF 分割・ファイル名自動生成ツール（統合版）`, 幅は約 780px 固定（`resizable(False, False)` の方針は従来どおり。一覧欄の高さ分だけ縦に伸ばす）

### 2.4 `preview.py`（プレビュー生成）

| 関数 | 入力 | 出力・挙動 |
|---|---|---|
| `build_preview(excel_path, sheet_name, cell, mode, output_dir) -> list[PreviewRow]` | 現入力のパス・シート・セル・モードID・出力先 | PDFページ数を得て、モードの `build_filenames` を呼び、各ファイルについて `exists`（出力先に既存か）と `duplicate`（大文字小文字無視で同一名が複数）を判定。`PreviewRow(page_no, filename, exists, duplicate)` のリストを返す。**ファイルの書き出し・既存ファイルの変更は一切行わない** |
- 表示用の整形（`[既存]` などの文字列化）はこの関数または行の文字列表現メソッドで行い、GUI は受け取った文字列をそのまま並べるだけにする
- FR-6 相当の不正（空欄・不正文字・予約名・数式キャッシュ無し）は `ValueError` をそのまま伝搬し、GUI はエラー欄に日本語表示する

### 2.5 データ仕様（共通の安全規則）

- 対応拡張子: PDF `.pdf` / Excel `.xlsx`, `.xlsm`
- 元のPDF・Excelは読み取りのみ。出力は `output_dir` 直下（一時フォルダーは `.pdf_split_*` を使い完了時に削除）
- Excel数式セル: 計算はしない（保存済みキャッシュ値を採用、無ければ中止）

## 4. 実行手順

### 4.1 アプリの起動

1. リポジトリ直下の `起動.bat` をダブルクリックする。
2. `py -3` → `python` の順で Python を探し、単一のメインウィンドウが開く。
3. 上部の共通欄（分割するPDF / Excelファイル / シート / 出力先フォルダー）を入力し、下部のタブで「セル値＋連番」または「セル別（連番なし）」を選ぶ。
4. 任意で「プレビュー」を押して出力予定ファイル名と `[既存]` / `[重複]` の印を確認する（プレビューで書き出しは起きない）。入力を変えると一覧は消え「入力変更あり: プレビューを更新してください」表示になる。
5. 「分割を実行」を押す。成功時は「Nページを分割しました／保存先」のメッセージが表示される。

### 4.2 テスト・検証（開発系）

テスト（プロジェクトフォルダーで実行）:

```text
python -m unittest -v
```

`.venv` を使う場合は `.venv\Scripts\python.exe -m unittest -v`。

独立検証（実PDF・実Excelを一時フォルダー `.pdf_split_verify_*` に作って機械判定。合否行と `TOTAL: <成功>/<総数>` を出力し、全件成功時終了コード0）:

```text
.venv\Scripts\python.exe tools\verify_independent.py
```

実装者側スクリプトとは別系統のアシスタント検証（項目設計を重複させていない）も同じ形式で合否行と `TOTAL` を出す:

```text
.venv\Scripts\python.exe tools\verify_assistant.py
```

GUIを一瞬だけ実ウィンドウとして表示し、描画確認後に閉じるスモーク（人の操作は不要・ウィンドウは自動で閉じる）:

```text
.venv\Scripts\python.exe tools\verify_gui_display.py
```

## 6. 既知の問題・留意点

- **開発機の `python` にライブラリが無い場合**: システムの `python` が `pypdf` / `openpyxl` を持たない環境では、テスト・検証はプロジェクト内 `.venv\Scripts\python.exe` で実行する（`起動.bat` はエンドユーザー機での自動 `pip install --user` を前提。実装委任時にエージェントによる pip 実行はしていない）。
- **重複名の扱い（FR-6 と FR-14 の両立）**: 実行時は大文字小文字無視の重複名で中止、プレビュー時は同じ入力でエラーにせず `[重複]` 印を付ける。この2面性のため `modes.build_filenames_per_cell` に `abort_on_duplicates`（既定 True）を設け、実行側は既定値・プレビューのみ False を渡す。要求文書 2.4 の「プレビューで伝搬させる不正は空欄・不正文字・予約名・数式キャッシュ」の列挙と整合させている。
- **base_seq 実行時の検査順序**: 参考コード（PDF-Split-Rename）では Excel → PDF の順だったが、統合版は両モード共通で PDF → Excel の順に単一化（PDF-Split-Rename-By-Cell 側に合わせて統一）。エラー文言自体は同じで、両方の入力が同時に不正なときの表示優先だけが変わる。
- **数式セル**: openpyxl は数式を計算しない仕様のため、数式変更後は Excel 側で再計算・保存が必要（エラー文言に案内済み）。
- **タブ切替時**: FR-15 の入力項目（PDF/Excel/シート/セル/出力先）に加え、モードそのものが変わるため一覧は「要更新」表示になる（実行時は常に現在のタブのモードで再計算）。
- **Python 3.14 以降の tkinter**: `tk.Frame(root, pady=(16, 8))` のようなウィジェット構築時のタプル詰め指定は `expected screen distance` のエラーになる（実環境 Python 3.15.2 で確認。参考コード2本は grid の `pady=(8, 12)` 形式のみ使用しており、grid のタプル指定は従来どおり動作する）。統合版は Frame・pack の詰め幅を単一値にし、細かい余白は grid 側のタプル指定で調整している。
