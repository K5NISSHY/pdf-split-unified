# OpenCode 実装依頼 — pdf-split-unified v1.0.0（統合版 PDF分割ツール）

## 0. あなたが今やること（1行）

承認済みの要件どおり、**既存PDF分割ツール2本を1ウィンドウに統合した Python/Tkinter アプリ**を、このプロジェクトフォルダーに新規実装してください。要件は本ファイルの第2章がそのまま仕様です（要件定義書 `docs/PROJECT_DOCUMENT.md` の第1〜3章と同一内容）。

## 1. 背景

すでに別リポジトリで2本のツールが存在し、その読み取り用の写しが本プロジェクト内の `refs/` に同梱されています。

- `refs/PDF-Split-Rename/pdf_splitter.py`
  → 指定セル1つの値をベース名にし、`{ベース名}_{ページ番号:03d}.pdf` で出力（連番モード）
- `refs/PDF-Split-Rename-By-Cell/pdf_splitter_by_cell.py`
  → 開始セルから同じ列を下方向へページ数分読み、`{セル値}.pdf` で出力（セル別モード・連番なし）

2本は UI・事前検証・一時書き出し・ロールバックのロジックがほぼ同一で、違いは**ファイル名の付け方だけ**です。
今回の統合では、共通部分を1本の共通コアにまとめ、モード差は「ファイル名リストを作る関数」だけに絞り込みます。
**新しい機能は追加しません**（追加は「ファイル名プレビュー」だけ。PDFのページ範囲指定や上書き実行などは対象外）。

参考コードは**読み取り専用**です。`refs/` 配下のファイルは変更・削除・リネームしないでください（実装はこの中のコードを流用・再構成して新規ファイルに書く）。

## 2. 仕様（承認済み要件 — これを厳守）

### 2.1 機能要件

| ID | 要件 |
|---|---|
| FR-1 | `起動.bat` ダブルクリックで**単一のメインウィンドウ**が開く（Python 3.10+ / Tkinter） |
| FR-2 | ウィンドウ上部に**共通入力欄**（分割するPDF / Excelファイル / シート / 出力先フォルダー）。両モードで同じ欄を共有する |
| FR-3 | 下部に**モード切替（ttk.Notebook でタブ2枚）**: タブ1「セル値＋連番」/ タブ2「セル別（連番なし）」。タブを切り替えても既存の入力は保持される |
| FR-4 | タブ1: 指定セル1つの値をベース名とし `{ベース名}_{ページ番号:03d}.pdf`（先頭 `001`、1000ページ超で桁数が伸びる） |
| FR-5 | タブ2: 開始セルから同じ列を下方向へページ数分読み `{セル値}.pdf`（連番なし） |
| FR-6 | 実行前に全件検査し、1件でも不正なら**処理を開始しない**: 空欄セル / ファイル名に使えない文字（`\ / : * ? " < > |`・制御文字）/ 末尾の空白・ピリオド / Windows予約名（CON, PRN, AUX, NUL, COM1-9, LPT1-9）/ 大文字小文字を区別しない**重複名**（タブ2） |
| FR-7 | 数式セルは計算せず、Excelブックに保存済みの計算結果を使う。結果が無い・空・エラー値（`#REF!` 等）は再計算を促す日本語エラーで中止 |
| FR-8 | 出力予定ファイルが1つでも既存なら**上書きせず中止**（既存ファイル名を最大8件＋「ほか N 件」で提示） |
| FR-9 | 全ページを出力先内の一時フォルダーへ書き出してから移動する。途中で失敗したら作成済みの出力を削除して後片付けする。**元のPDF・Excelは変更しない** |
| FR-10 | 暗号化PDFは空パスワードで解除を試み、開けなければ日本語エラーで中止。破損PDF・読み込めないExcelも日本語エラーで中止 |
| FR-11 | 成功時は「Nページを分割しました／保存先」をメッセージボックス表示。エラー文言は参考コード（`refs/`）と**同じ意味・同じ表現**を維持する |
| FR-12 | 参考コード2本の単体テストを1ファイルに統合し、共通コアとプレビューのテストも追加する（`python -m unittest -v` で実行できること） |
| FR-13 | 独立検証スクリプト `tools/verify_independent.py` を持つ（第2.4節参照） |
| FR-14 | **ファイル名プレビュー**: 「プレビュー」ボタンで出力予定ファイル名の一覧をウィンドウ内の一覧欄に表示（データは全件、表示12行程度＋100件超は末尾に「ほか N 件」）。行に印を付ける: 出力先に既存ファイルがあれば `[既存]`、タブ2で大文字小文字無視で同一名があれば `[重複]`。**プレビューで書き出しは一切行わない**。FR-6 の検査対象の不正はその場で一覧下のエラー欄に日本語表示する |
| FR-15 | プレビュー後に入力（PDF/Excel/シート/セル/出力先）が変わったら一覧を消して「入力変更あり: プレビューを更新してください」表示。実行時は常にその時点の入力で再計算する |

### 2.4 独立検証スクリプト（`tools/verify_independent.py`）

一時フォルダーに実データを作り、両モードで分割を実行して**機械的に合否を出す**（表示用数値を手で書かない）:

1. 3ページの空白PDFと、A1〜A3 に `あいう / かきく / さしす` を持つExcelを生成
2. `base_seq`（A1）→ `あいう_001.pdf`, `あいう_002.pdf`, `あいう_003.pdf` が生成され、各PDFがちょうど1ページであること
3. `per_cell`（A1）→ `あいう.pdf`, `かきく.pdf`, `さしす.pdf` が生成され、各1ページであること
4. 同じ出力先で再実行すると `FileExistsError` で中止し、既存ファイルの中身が変わっていないこと
5. 空欄セル（タブ2でA2を空）→ 実行前に中止し、出力ファイルが1つも作られていないこと
6. 重複名（`Report` と `report`）→ 重複エラーで中止
7. プレビュー（`build_preview`）の返す行が、4 の状況で `[既存]` / 6 の状況で `[重複]` を正しく付けること（書き出しが発生していないことも確認）

PASS/FAIL を1行ずつ、最終行に `TOTAL: <成功>/<総数>` を出力する。終了コードは全件成功時 0、そうでない時 0 以外。

## 4. 厳守事項（違反すると差し戻します）

1. **`pip install` 等のパッケージ導入コマンドを実行しない**（環境は用意済み）
2. コマンド実行は**プロジェクトフォルダー内**だけ。プロジェクト外のファイルを読み書き・削除しない
3. `refs/` 配下を変更しない
4. Pythonは次の実行環境を使う（PowerShell。パスはプロジェクトからの相対で書く）
   - テスト: `python -m unittest -v`（`python` が無ければ `.venv\Scripts\python.exe -m unittest -v`）
   - 検証: `.venv\Scripts\python.exe tools\verify_independent.py`
5. 実行確認のために GUI を**表示**しなくてよい（`tkinter` のウィンドウは開かない。ロジックのテストと検証スクリプトの実行で確認する）
6. コードのコメント・UI文言・エラー文言は日本語（識別子とコメント内の技術名は英語可）
7. 生成ファイル（`__pycache__/`, `.venv/`, 一時フォルダー `.pdf_split_*`）をコミット対象にしないよう `.gitignore` に入れる（git の init / commit は**あなたがやらなくてよい**。私が行います）
